## G06 — ownership, exact continuation and events

- Persist exact listing, package, source channel and release digest before check/download/install dispatch. The SQLite event journal uses transactional revision updates, separates actual queue/stage observations from install confirmation, stores bounded error classifications and exposes batch completion counts (including failures).
- Check and transfer use separate per-listing cross-isolate transaction locks. Destination guards protect cache writes and metadata mutation. A known process identity includes PID/start tick/boot identity; unreadable evidence never proves death. Recovery is read-only for native approval and uses existing exact R05/native reconciliation; no approval token is recreated from history.
- Explicit Resume validates original job, origin, entity validator, release, cache owner, block hashes and exact returned 206 range. Invalid explicit resume refuses without falling back to fresh installation. Ordinary download retry keeps the previous verified checkpoint on pre-write failure. Retry of a failed installation is a separate reviewed child attempt; previous receipts stay immutable. Cancel targets current owner or exact queued intent; older receipt IDs never authorize another operation.
- Source and local-file preparations bind to their actual R05 attempt. Local artifact bytes have a domain-separated identity, not fabricated remote provenance. The local import's package/listing cannot be bound before manifest inspection; its pre-identification extraction remains the existing private staging flow, not a source-bound listing operation.

## G07 — bounded view, safe archival and retention

- Terminal R05 records move atomically out of the recovery namespace. R03 terminal metadata moves only when its exact known cache owner has no retained artifact, partial or extracted directory. Unknown or unresolved ownership is retained; legacy unknown-channel entries are read-only. No age- or prefix-based deletion of recovery bytes.
- Read-only Activity Center exposes independently readable records and integrity warnings. All unresolved rows remain visible independently of finished-history size; finished entries are selected by scope and paginated. The SQLite timeline uses an indexed finished-history query. Historical R03/R05 scans stream individual records; total scan time remains proportional to receipt count, but retained finished rows are bounded by the requested page. Explicit export can load complete scoped history.
- Retention previews exact immutable metadata identities and revalidates channel/listing/package, record content and actual transfer-cache ownership before deletion. R05 parents referenced by children stay protected. The deletion of install and transfer metadata is not one cross-journal transaction; on an error the UI reports interruption and refreshes, never claims all requested deletions. The timeline retains its event history; this overlay does not silently prune events linked to retained or removed receipts.

## HF02 — durable SQLite concurrency

The exact GAP-03-HF01 head `883f17f800e58b76b7a3f9cfd8f429446b7a85df` passed strict analysis, dedicated GAP-03 tests and five of six required workflows. Full Flutter job 140104084889 failed bulk refresh on `BEGIN IMMEDIATE` (`SQLITE_BUSY`, code 5); independent R03/R05 ownership tests also emitted contention during `PRAGMA user_version`. Separate connections and blocking busy handlers in the common worker can delay the very owner needed to release the lock. Serialize all short timeline transactions and exact per-identity guard acquisition by path inside each isolate. Preserve SQLite transaction ownership across isolates/processes; disable blocking busy waits for these connections and retry only classified BUSY/LOCKED on open or BEGIN before callback entry, using bounded asynchronous waits. A callback, commit or close error must never cause replay. Recovery and opportunistic archival use short bounded acquisition and skip only typed acquisition contention; unrelated storage errors remain visible. Bulk initiating/joining callers share one failure result without a duplicate unobserved completer error. Tests cover actual independent-connection contention, acquisition deadline, rollback/non-replay, independent identity progress and the original multi-listing bulk integration, with all existing receipt retention protections intact. New hosted runtime and device acceptance remain pending.
