# R12 — Full qualification, packaging and release

**NO PUBLIC RELEASE QUALIFIED.** The candidate workflow is an evidence producer, not a publisher. Keep the six existing exact-head PR workflows and all physical/live acceptance outstanding until verified. No credential provisioning, merge, tag, dispatch, installation on a personal device or publication is authorized by implementing this overlay.

## 1. Source and hosted acceptance

- PR #30's exact GAP-05 predecessor (`97b9cda75852889343fef71d48259f69b6adae2e`) passed the six required hosted workflows. It is historical evidence, not R12 or post-merge evidence.
- Run the same six full lanes on the exact reviewed `main` SHA after an explicitly approved merge. The existing workflows support manual dispatch; no dev-only scoped results or synthetic merge results qualify. The R12 lane reads actual run/attempt/job/decisive-step identities on exact main, rejects missing, stale, skipped and newer failed runs, and reobserves before signing. It does not change the required PR check inventory.
- The separate `.github/workflows/obtainx-r12-candidate.yml` is **manual only**, protected `main` only. Wrong context or SHA fails, rather than yielding a successful skipped job. It runs complete `dart format --output=none --set-exit-if-changed`, strict Flutter analysis, Flutter tests, source-contract regression and workflow guards. Formatting debt must be fixed in a reviewed source change; no auto-format inside the release build or silent exception.
- Two independent, disposable hosted runners resolve the exact lockfile, build unsigned normal release-mode split-by-ABI APKs, independently hash the bytes and contents, verify package/ABI/version/minimum API/no debug status and alignment, and retain the resolved dependencies, toolchain and CI evidence. Compare exact unsigned bytes and inventory; reproducibility failure stops the signing job. This is unsigned build reproducibility on the recorded toolchain, not a claim of signed-byte reproducibility across all signers or OSes.
- The candidate lane inventories Pub hosted hashes, Git resolved commits, SDK/local dependencies and resolved Android Maven coordinates. It collects license-file/POM hashes and license metadata, produces CycloneDX dependency inventory and checks public Pub/Maven/commit advisories using OSV. Missing/paginated advisory results or known findings refuse signing. License obligations, SDK/local code, known advisory scope and full supply-chain/secret-scan coverage still need independent security review. The bounded tracked-source and expanded APK secret-signature checks are supplemental, not proof of absence of every possible secret.

## 2. Protected signing prerequisites (external, explicit approval only)

Before any dispatch, independently verify that `main` is protected and the GitHub environment **`obtainx-release-candidate`** restricts deployment to protected main, requires an independent reviewer, prevents self-review and has no administrative bypass of the agreed review. The workflow does not create or configure the environment; its existence and review policy must be confirmed outside the checkout. Do not use repository-wide signing secrets; provision only environment secrets:

- `OX_RELEASE_KEYSTORE_B64`: base64 of a **new** protected release keystore; never reuse the public legacy wizzwuz key.
- `OX_RELEASE_STORE_PASSWORD`, `OX_RELEASE_KEY_PASSWORD`, `OX_RELEASE_KEY_ALIAS`: private values from the same reviewed identity.
- Environment variable `OX_RELEASE_CERT_SHA256`: the independently pinned lowercase 64-hex SHA-256 of the new signing certificate. Confirm out of band that it is not the legacy signer and belongs to the controlled key. Never send the key/passwords in a chat, commit, command line, log, artifact or receipt.

The isolated signing runner never builds project dependencies. It fetches only the current run/attempt's two unsigned inventories, rechecks each APK and evidence digest, reobserves CI, compares the independent builds, and signs only after approval and complete credential validation. Keystore bytes exist only in private temporary storage and passwords go to `apksigner` via environment, never command-line values. Verify each final APK with the pinned Android tools, require a single expected signer and unchanged ZIP payload, record signed bytes and source tree. The candidate is retained as a time-limited Actions artifact; no GitHub Release, tag or publication mutation. Missing credentials, wrong signer, invalid signature, wrong package, debug, ABI mismatch, evidence drift or irreproducibility fail closed.

The legacy arbitrary-directory `sign.sh` is retired. `build.sh` now only creates unsigned developer builds and never syncs/pushes/upgrades/signs. Existing Gradle unsigned release-mode output is intentionally supported for independent reproducibility and F-Droid builds; it is never release acceptance. Do not publish it. `normal`/`fdroid` share package identity, so cross-channel updates need the exact same authorized signer. The R12 candidate covers **normal** three ABI APKs only; F-Droid integration/signing and any cross-channel claim require separate evidence.

## 3. Migration and device evidence

The old distributed signer is not trusted for new release authorization. A different certificate cannot ordinarily update the old installed app. Do not uninstall a user's app automatically, export private data without consent, lower signature checks, or imply seamless migration. First test export/restore with disposable fixtures, document the new signer fingerprint and reviewed backups (excluding credentials), ask users to review before uninstall/reinstall, and verify old-signature rejection and correct new-signer update. No automatic migration or key rotation claim.

Use `scripts/ci/r02f_p05_physical_probe.py --serial <authorized-device> --ack I_AUTHORIZE_READ_ONLY_DEVICE_PROBE` only after consent to inventory a device. This read-only probe is not qualification. Use separately approved disposable installation fixtures; inspect positive, negative and cancelled outcomes and retain exact installed APK/package/version/certificate/digest and backend evidence, not screenshots alone. Do not install on a personal device or enable privileged backends without approval. `scripts/ci/r12_device_evidence.py` defines the required eleven lanes, rejects missing/stale/wrong-APK or duplicate evidence, and retains explicit `PENDING_EXTERNAL`/`UNSUPPORTED` reasons; neither is success. It verifies downloaded signed candidate bytes and all primary receipts again with the pinned tools. An evidence-complete result is still subject to independent human review of actual observations. Use the same source SHA/tree/certificate and exact candidate APK SHA in each lane. Logs must be sanitized. Each lane needs its own evidence file(s), reviewer, timestamp, Android API, backend, authorization and positive/negative outcomes as specified in `MATRIX`. No physical activity was performed by this source change.

### Device matrix format

Use schema `obtainx.r12.device-matrix.v2`; v1 evidence is refused, not upgraded into acceptance. Repository, source SHA/tree and certificate bind all rows. Pending rows have a reason and no observations. PASS/FAIL rows include exact APK filename/digest/ABI, RFC3339 UTC `observed_utc`, reviewer, lane-specific `backend` and `device_kind`, Android API (exactly 36 for the API36 emulator lane), `authorized_fixture: true`, and `observations` keyed by the exact `LANE_RULES` check IDs. Each reference `{path, sha256}` identifies a distinct `obtainx.r12.device-observation.v2` JSON document with repository, source SHA/tree, certificate, APK filename/digest/ABI, lane, check, expected/actual outcome, timestamp, reviewer, backend, device kind, SDK, fixture approval, and distinct `attachments` (`{path,sha256,kind}`). Every observation requires a sanitized log or receipt; screenshots alone are insufficient. Every observation includes independently observed candidate package/version/certificate/APK digest; it must equal the signed candidate. Installed target checks include independently observed package/version/certificate/APK digest. Installer refusal and cancellation checks retain matching before/after target identity (or explicit absence) and prove no owned session remains. The target can be a disposable fixture distinct from ObtainX. Reused evidence content, names, stale bindings, contradictory outcomes and malformed timestamps are refused. This structure verifies evidence completeness, not authenticity; actual observations require independent human review. No automatic release or publication authorization.

## 4. Acceptance and publication

`SOURCE_PASS`, `HOSTED_CI_PASS`, `DEVICE_RUNTIME_PASS`, `RELEASE_QUALIFIED` remain distinct. The signed candidate records source and exact main hosted checks, unsigned reproducibility, APK metadata/cert/hash and provenance; device and independent security/license/migration review remain separate. Do not count incomplete checks, missing SDKs, unreviewed license metadata, scoped runs, unsupported backends or inaccessible devices as PASS. The v1.37 operator may deliver the implementation while external gates remain pending. An independently reviewed exception must be explicitly approved, bounded and recorded; it cannot claim full qualification. A subsequent separate explicit publication approval is required even if all acceptance gates pass. No workflow in R12 publishes an APK or tags a release.

Android uses the existing Flutter-provisioned Gradle wrapper, pinned by `android/gradle/wrapper/gradle-wrapper.properties`; the wrapper is generated by the reviewed Flutter SDK rather than committed. Direct Gradle commands on hosted runners occur only after Flutter has provisioned it. Local agent Gradle execution is prohibited. Shell source qualification includes the Bats behavioral harness. Hosted R12 runs Bats and ShellCheck, checks the standalone translation utility with Node's native syntax/test runner and pinned ESLint, then verifies Android lint and tests after Flutter's build has provisioned Gradle.
